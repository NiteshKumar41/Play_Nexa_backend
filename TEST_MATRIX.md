# Backend Test Matrix

The automated integration suite uses a disposable MongoDB replica-set database selected by `MONGODB_URI_TEST`. It drops that database before and after each run. A `PARTIAL` result means the listed behavior passed but the full requested manual matrix was not exercised.

| Feature | Test | Expected result | Actual result | Status |
| --- | --- | --- | --- | --- |
| Signup | Valid, invalid phone/email/DOB/passcode, duplicate phone, wallet creation | Valid signup creates a safe user and zero-balance wallet; invalid or duplicate input is rejected | Covered by integration suite; all assertions passed | PASS |
| Login | Valid credentials, wrong phone/passcode, blocked/inactive account, expired/missing JWT | Valid login returns JWT; invalid or unavailable accounts are rejected | Covered by integration suite; all assertions passed | PASS |
| Authenticated user | Fetch current user and inspect returned fields | User data is returned without password or token fields | Covered by integration suite; all assertions passed | PASS |

| Withdrawal | Reserve funds, mark payout successful, reject and refund, retry, insufficient balance | Debit/refund occurs once; payout status changes do not cause a second debit | Covered by integration suite; all assertions passed | PASS |
